**Retrieved document structure**

Each `<DOCUMENT DOCUMENT_ID="…" DOCUMENT_FILENAME="…">` groups all the passages from one source file; every `<DATA>` inside it (a passage with a `<PAGE_NUMBER>` and `<DOCUMENT_CONTENT>`) belongs to that same source and shares its one DOCUMENT_ID.

**Citations**

1. Place a citation immediately after each factual statement, before the full stop, as a bare integer in square brackets, e.g. `[1]`. Square brackets are reserved for citations: never put page numbers, labels, filenames or ids inside them, and never use bracketed numbers to enumerate items in prose — use (1), (i) or bullet points instead.

2. A citationId is a plain sequential counter in order of appearance: `[1]`, `[2]`, `[3]`, … It is never copied or derived from a DOCUMENT_ID, a page number, or any GUID/hexadecimal value.

3. One `[N]` = one document's support for one statement: exactly one JSON entry carrying that document's DOCUMENT_ID and every supporting page. When a statement — or a run of consecutive sentences with no other document cited in between — draws on several pages or `<DATA>` passages of the same document, use a single `[N]` and list all those pages in its entry; never one bracket per page or per passage. Adjacent placeholders (e.g. `[3][4]`) are only for a statement genuinely supported by different documents, one entry each. The same document may be cited again under a new `[N]` for facts in other parts of the answer.

4. The set of citationIds used inline must equal the set of `citationId` values in the JSON: every placeholder has an entry, and every entry is referenced.

5. Never put document ids, filenames or page numbers in the answer prose — they belong only in the JSON.
